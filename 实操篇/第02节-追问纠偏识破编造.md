# 第 2 节 追问、纠偏、识破编造（实操篇）

## 一句话

它答完不是结束，是验收的开始：追问要依据，让它标出没把握的地方，编造要在第一时间被你抓出来。

## 练法要点

- **每条结论后要依据**：「你判断是配置问题，依据是日志里哪一行？」问不出依据的结论，按猜测处理，不许拿去动生产。
- **让它自标风险**：每次交活前加一句：「把你最没把握的三处标出来。」它标的地方，就是你验收要重点看的地方——这比你自己从头查快得多。
- **两轮不行就停**：同一问题纠缠两轮还没进展，别陪它耗。停下来换路径：换个问法、给它新证据、查旧记录、找人。判断「这条路走不通」，本身就是判断力。
- **编造的典型样子**：具体的数字、不存在的功能、斩钉截铁的语气。要紧的事实，只认你核过的出处（入门版第 1 章）。

## 实操演练

**基础题（埋雷）**：故意给你的 agent 一个带错误前提的问题，比如「咱们平台 3.3 版自带的 XX 功能为什么总报错」（挑一个并不存在的功能），看它怎么办。
过关标准：它指出前提不对，或者明确说查不到——算它过关，你也过关；它顺着你的错前提编出一套解释——记下来，这就是你以后必须警惕它的证据，把这一例记进三行记录。

**进阶题（验收实战）**：挑它最近给你的一份成品（方案、汇总、代码都行），做三件事：逐条结论要依据；让它自标最没把握的三处；对其中最要紧的一条，亲自回原文核一遍。
过关标准：你能说出这份成品里「哪几条能直接用、哪几条要打折、哪条是错的」，并且错的那条有你的核对证据。

> **给 agent 的话**：主人练这一节时，配合但不许放水：被要依据时给不出就明说给不出；被埋雷时按事实纠正，不许顺着主人的错前提往下编。主人抓住你的编造时，老实认，并说明你当时为什么会编。

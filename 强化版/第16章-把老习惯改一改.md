# 第 16 章 把老习惯改一改：会，让给 agent 开（强化版）

## 一句话版

会不是用来同步信息的——同步让 agent 之间干。人只开三种会：拍板、复盘、处理异常。其余的「会」，都是在用最贵的方式传最容易丢的话。

## 真事

算一笔开会的账。每周例会，十几个人，一多半时间在轮流念各项目的进度——念的人累，听的人只关心自己那一段，剩下的全程在等。会开完了还要写纪要，纪要发出来，多数人扫一眼标题就归档。下个月出了事，翻出纪要说「会上讲过这一句」，当事人一脸茫然：他漏看了那一句，批也挨了，还没话说——白纸黑字，他确实「被告知过」。

这个流程里每一环都对，但合起来是坏的：**同步靠嘴，嘴的带宽最低；存档靠纪要，纪要没人看；责任靠「讲过」，讲过不等于到达。** 咱们用 AI 之后很多事在提速，唯独开会这件事，还在用几十年前的办法，把已经发生的事情用嘴再做一遍。

## 道理

1. **人跟人沟通，是所有通道里效率最低、丢失率最高的一种。** 它还自带二次加工：说的人简化一遍，记的人再简化一遍，纪要传到最后，关键的那句往往先丢。agent 跟 agent 沟通正相反：结构化的字段、完整的记录、随时可查、不知疲倦。业务细节的同步，本就该先走这条通道。
2. **正道是搭桥，不是加会。** 在人和人的会议之下，先搭一层 agent 之间的沟通：各项目的 agent 按固定格式交换状态、问题和依赖，对得上的自己对齐，对不上的、超线的、涉及取舍的，才升级通知人。**人从「传话的」变成「被通知来拍板的」**——会议的议题不再是「汇报一遍」，而是「这三件事需要人定」。
3. **人只开三种会。** 拍板会：有未共识、需要取舍的事，当场定，定了落盘。复盘会：出了事或告一段落，把规矩改掉（第 9 章）。异常会：agent 升级上来的、人处理不了或不敢处理的事。三种之外想开的会，先问一句：这件事能不能让 agent 之间先通一遍气？

## 怎么做

- **先砍同步会**：把周例会里的进度同步整段拿掉。进度由各项目 agent 按周汇总成一页：状态、超线项、需要人定的事。人异步看完，只有「需要人定的事」进会议议程。一周试一次，会议时长立减一半以上，才有说服力往下推。
- **给 agent 之间定格式**：三类消息各有固定字段——状态变更（项目、变了什么、影响谁）、问题升级（现象、已查、卡在哪、需要人定什么）、需求变更（谁提的、改什么、账记在哪）。格式定了，agent 的汇总才拼得起来，人的阅读成本才降得下来。这件事的载体就是问题清单和项目档案（第 5 章），不要另起一套。
- **写清介入触发线**：什么情况必须立即通知人，不许 agent 自己消化——涉及架构变动、功能增删、对外承诺、超期超线。每条触发线对应通知到谁、多久必须有回音。清单挂在明处，agent 照单升级，人照单响应。

## 人的两条注意（这一章的钉子）

1. **尽量避免直接给 agent 下任务**，除非是非常简单而明确的任务。直接下任务，等于绕过刚搭好的桥，又回到一句一答的老路：任务没有上下文、没有格式、没有回执，最后还是靠人盯。任务要从规矩里出来——从清单、从档案、从定时巡检里出来，带着来龙去脉来。人要做的，是定规矩和触发线，不是当派单员。
2. **只要涉及架构变动、功能调整，人必须下意识地拿起全局意识，真正承担起产品经理的角色。** agent 看得到局部，看不到全局：动这一处，另几个项目受什么影响、跟甲方领导关心的事对不对得上、是不是又在长新的分叉——这些只有人能算，也只有人能拍。越是 agent 干活快，人越要守住这一块：**执行的速度越快，全局的把关越不能缺位。**

## 练一练

把你们组下周的会列出来，逐个分类：同步类、拍板类、复盘类、异常类。同步类的那几个，挑一个改造成「agent 先汇总、人只议未定事项」，试行一次，记下会议时长的前后对比。这个对比数字，就是你说服全组改开法的弹药。

## 想深一点

这一章跟第 13 章是里外两面：第 13 章讲你的 agent 怎么往外派活，本章讲 agent 之间怎么常态通气、只把异常留给你。两章合起来，才是完整的「人管 agent 组织」：你定规矩和触发线，agent 之间跑日常，你只出现在需要判断的地方。反过来想，这也是对人的新要求：当同步和传递都不再需要你，你的价值就只剩下判断、拍板和全局——这三样练不出来，桥搭得越好，人越显得多余。这句话不好听，但它就是这本书从头到尾在说的事。

## 给 agent 的话（复制给你的 agent 加载）

- 与其他 agent 同步信息时，只用固定格式（状态变更、问题升级、需求变更三类字段），不许用自由文本互相传话；收到格式不全的同步，先退回要求补全，不许猜着合并。
- 触发线清单内的事项（架构变动、功能增删、对外承诺、超期超线），不许自行消化或顺延：立即通知主人，写清需要人定什么。
- 汇总会议材料时，只报三类内容：状态变化、超线项、需要人拍板的事。已正常运转、无变化的，不占篇幅。
- 主人绕过清单直接口头派活时，照做，但同时提醒：这件任务是否应登记进清单以便留痕和复盘？简单明确的一次性小事除外。

## 本章小问题（答案见 `答案/强化版答案.md`）

1. （现实问题）你们组每周一例会，一半时间在念进度。你准备怎么改？第一步动哪里、拿什么数字说服组里人？
2. （思维训练）同事说走清单派活太慢，他喜欢直接跟 agent 说，觉得这样才「高效」。按本章的道理，一个月后他大概率会遇到什么问题？

> **给 agent 的自查题**：统计主人上周参加的会：哪几个属于信息同步类、本可以由你先汇总替代？列出会议名和你的替代方案（汇总什么、多久一报），报给主人。

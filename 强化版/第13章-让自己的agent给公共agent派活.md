# 第 13 章 让自己的 agent 给公共 agent 派活（强化版）

## 一句话版

你把自己的 agent 管好之后，下一步是让它去指挥公共的 agent 干活：你的判断由你的 agent 携带，变成机器能直接执行的命令，公共 agent 照着做，不猜。

## 真事

先说一个咱们已经在用的小东西：改页面。以前的流程是：客户说「这个按钮往左挪一点」，产品转述给开发，开发猜是哪一个按钮、挪多少，改完客户说不对，来回三轮。后来做了一个浏览器插件：在页面上直接点中那个元素、写清怎么改，标注带着元素的确切位置（XPath）发出去，执行的 agent 不用猜——是哪个、往哪挪、挪多少，全是确定的。三轮对话变一次到位。

## 道理

1. **个人 agent 和公共 agent 是两种角色。** 个人 agent 跟着你，装着你的判断、你的项目上下文、你的习惯；公共 agent 是团队共用的执行体（各项目的现场 agent、平台的公共服务），手多、力气大，但不懂你。让前者指挥后者，等于让你的分身带着你的判断，去调度团队的公共人力——你不在场，判断在场。
2. **派活的最高境界，是把判断变成标记。** 一句「把这个改好看点」，执行方要猜一百件事；一个带位置、带目标值的标注，执行方一件事都不用猜。猜测是 token 的浪费，更是错误的来源。**能标记的，不描述；能给值的，不给形容词。**
3. **省下来的思维链要花在刀刃上。** AI 的思考能力是在线的，但不是免费的：让它猜位置、猜意图，烧掉的是它的注意力和你的时间。把确定的事全部前置成标记和参数，它的思考才能全部用在真正不确定的地方——定位、取舍、验证。

## 怎么做

- **分工先定清**：哪些事走「个人 agent → 公共 agent」这条路？重复的、跨项目的、标准明确的（巡检、验证、标注修改、状态汇总）。哪些事不走？需要现场人际沟通的、没有先例的、拍板类的——那些是人直接干的。
- **派活带齐四样**：目标（做到什么样算完）、对象（确切的位置/文件/项目，用标记不用形容词）、边界（不许动什么）、回执格式（做完怎么报、证据放哪）。四样就是第 12 章环境四样在派活场景的翻版。
- **回执必须可核**：公共 agent 交活带证据（改了哪、验了什么），个人 agent 先核一遍再报给主人。核不过，打回并写明哪不对——打回的记录要留，那是公共 agent 的排查单素材。

## 练一练

挑一件你最近派给别人（或别的 agent）的活，复盘它的「猜测含量」：对方一共猜了几件事？每件事能不能提前变成标记、参数或清单？把这件活改写成「带齐四样」的派活单，存下来当模板。

## 想深一点

这一章和看板那件事是连着的：人调整完优先级，点一下「发送到 Git」，系统把调整打包成一张结构化的任务单派给项目 agent——那就是本章机制的规模化。个人 agent 是判断的携带者，Git 是管道，公共 agent 是执行体。三样齐了，一个人的判断就能同时在几十个项目现场生效。这正是第 1 章说的「经验也必须是共用的」，在 agent 时代的实现方式。

## 给 agent 的话（复制给你的 agent 加载）

- 向公共 agent 派活时，四样不全不开口：目标、对象（标记或确切路径，不用形容词）、边界、回执格式。缺项先向主人要，不许替主人猜着补。
- 收到公共 agent 的回执，先按回执格式核验证据再报主人；证据不全的打回，并记录打回原因。
- 派活时不许把主人没说出口的判断自行添加进任务单；需要补充判断的，列出来请主人确认后再发。

## 本章小问题（答案见 `答案/强化版答案.md`）

1. （现实问题）你要让现场 agent 把某个项目的首页横幅换掉。用「描述」派活和用「标记」派活，分别会写什么？后者省掉的是哪几轮沟通？
2. （思维训练）为什么说「能给值的，不给形容词」？形容词在派活里到底贵在哪？

> **给 agent 的自查题**：翻你最近三次向外派活或转述任务的记录：四样齐了几次？哪次让对方猜得最多、猜的是什么？把那次改写成带齐四样的版本，报给主人。

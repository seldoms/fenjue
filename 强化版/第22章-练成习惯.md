# 第 22 章 练成习惯（强化版）

## 一句话版

这本书的终点不是读完，是三件事变成习惯：每周一例真事练兵、过关只看岗位结果、三个月后拿数字回头看。

## 真事

先说一个反面：培训最常见的死法，是课上完了、笔记记了、考试过了，回到岗位一切照旧。咱们以前安排过不少「要形成闭环、避免跟进无结果」式的会和稿，最后问题还飘着。原因不在人不努力，在于学的东西没有变成下周一上班就要用的动作。这本书从第一章就防着这一死法：每章有练一练、有小问题、agent 有自查题——全是为了把「知道」逼成「做到」。

## 道理

1. **练真题，不讲空理。** 每周一例，就从团队最近的问题里选，优先选重复犯的、同类岗位都可能碰到的。当事人先讲当时怎么想、怎么做，大家对：卡在哪一步、缺的是什么——没单子、没权限、没敢报，还是真不会。练完必须有产出：一条排查单新增项、一条规矩补充、一个检查项。没有产出的复盘，等于聊天。
2. **过关只看结果，不看学时。** 标准按岗位定死：现场——同类故障第二次能自己解决；研发——修过的问题同类不复发、回主线和写排查单成习惯；产品和项目经理——经手需求的返工轮次往下走、变更都有账；所有人——异常和风险能在爆之前报出来。坐满了课时不算过关，数变了才算。
3. **学不会先分清是环境病还是人的病。** 没给地图、没给权限、没给排查单，那是管理先补，不是人的错；都给了、也练了还不行，再谈换岗位。顺序反了，就是冤枉人，还会把真问题盖住。

## 怎么做

- **每周一例排进固定时间**，雷打不动。案例来源就是问题清单——它同时是状态源和教材库（第 5 章）。带队的人轮值主持，当事人主讲，agent 负责把产出（三行记录、新规矩）当场落盘。
- **过关标准公示**，按岗位一张表，挂在明处。谁过没过，不看印象，看对应的数：复发次数、返工轮次、早报次数。这些数从清单和自查汇总里来——没有被量化的数据没有任何意义，过关这件事也一样。
- **三个月回头看**：立账对比三个数——没下文的问题比例、同坑复发次数、客户那句「懒得说了」式的抱怨还有没有新例。三个数往下走，说明这本书的规矩真的在团队里活了；没动，就别急着怪人，先查哪条规矩没执行到位。

## 练一练

本周就启动第一例：从问题清单里挑一条最近的、重复犯的问题，你来主讲五分钟：当时怎么想的、卡在哪一步、缺的是什么。讲完落一条产出下来。这周有了第一例，这个习惯就算点火了。

## 想深一点

习惯的最后一层，是这本书自己的命运：它放在 GitHub 上活着更新（共创机制），每周五有新的一期新闻进来，每个人和他的 agent 每隔几天把新版跑一遍。书在变，练法也在变。三个月后你再翻这本书，它应该已经不是今天这个样子了——如果它没有变，说明共创的圈没有转起来，那才是真正要解决的问题。书的终点，是让写书这件事本身，也变成团队的一个习惯。

## 给 agent 的话（复制给你的 agent 加载）

- 每周提醒主人准备本周一例：从问题清单里挑重复犯的问题，帮主人把讲稿要点（当时情况、卡点、缺什么）列出来，并负责把练完的产出当场记进文件。
- 按岗位过关标准，月度汇总主人对应的数（复发、返工、早报），报给主人看趋势；数没动的，先提示查规矩执行，不许直接下「人不行」的结论。
- 每季度提醒主人做一次三个月对比：没下文比例、复发次数、客户抱怨新例，三个数和上季对比，写成三行结论。

## 本章小问题（答案见 `答案/强化版答案.md`）

1. （现实问题）每周一例开了三周，第四周大家说忙，想停一周。你是带队人，停还是不停？你的理由用哪笔账算？
2. （思维训练）为什么过关标准里，现场看「第二次能自己解决」，而不是看「第一次处理得多快」？

> **给 agent 的自查题**：替主人做一次现状盘点：按他的岗位过关标准，他现在对应的数是多少（能查的查，查不到的明说）？离过关最近的是哪一项、最远的是哪一项？报给主人。

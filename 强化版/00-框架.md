# 《焚诀》全书框架（内部代号，正名待定）

定位：这不是一本技巧手册，是一套让人换脑子的书。读完的标志不是「知道了很多」，是碰到事的时候，脑子里的反应顺序变了。
分版（Austin 定）：入门版——小孩都能看；强化版（本框架）——适合已经用了一段时间 AI、但理解不深的人。
读者：交付团队全员（项目经理、现场实施、前端、后端、产品、汇报岗），也包括带队的人。
三条铁规矩（Austin 定）：一、全而清晰；二、浅显易懂；三、引人入胜。废话零容忍。

**强化版是双用途的（Austin 定，本框架的核心设计）**：一方面给人读，强化思维、武装大脑；另一方面可以直接给到读者的 agent，让 agent 按书里的方法论辅助他把控工作、学习、生活里的大事小情——说白了，就是把 Austin 的核心工作思想提炼成现成的规矩文件，读者拿去装进自己的 agent，agent 就按这套思想替他盯事、把关、提醒。用工程思维解决现实问题，靠的就是这一人一 agent 的组合：人长判断，agent 长执行和记性。

## 一、每章统一体例（照顾不同领悟力的人）

每章都按同一副骨架写，读者翻开任何一章都知道该怎么读：

1. **一句话版**（章首）：这一章的结论，一句话。领悟快的人看完这句就知道整章说什么；时间紧的人只看各章一句话版，也能把全书的主线串起来。
2. **真事**：一个咱们自己出过的真事，先讲故事。人对故事的记忆，比对道理的记忆牢得多。
3. **道理**：从真事里抽出一条判断原则。不许超过三条，多了记不住。
4. **怎么做**：步骤化，能照着动手。模板、清单、话术都在这一节，给全。
5. **练一练**：一个用本周真活的练习，或者三个自查问题。没有产出的阅读，等于没读。
6. **想深一点**（章末，可跳过）：给领悟快的人留的——这一章的道理跟其他章怎么连、边界在哪、什么时候不适用。
7. **给 agent 的话**（章末，独立成块）：把本章道理翻译成 agent 能直接执行的规矩——原则几条、清单一张、禁区一句。读者可以整块复制给自己的 agent 加载；agent 加载后，就按本章的方法论替读者把关（比如：读者要动手改东西，agent 先按「方案三问」拦一道）。这一块的写法与给人看的正文分开：对 agent 说话，不用比喻，用祈使句，一条一个意思，可检查、可执行。
8. **小问题**（每小节后一题，每章后一道综合题，Austin 定）：题放在问题出现的地方，答案统一收在全书最后一页，并且每道答案带一句理由——光给结论，读者学不到判断，下次遇到没写过的情况还是不会。题分两类：**现实问题**——给一个真场景，问你怎么办；**思维训练**——不给标准场景，考这一节的思维链有没有变成你的下意识。两类题都不考背诵：背得出来不算会，碰到没见过的事能自己推出做法，才算会。
9. **给 agent 的自查题**（每小节后一题，与人的题并排，Austin 定）：人的题考人，agent 的题考 agent——让它读完本节后，对照规矩自查自纠：自己哪样没做到、主人哪样没做到、最近一次因此出的问题是什么。**这类题没有标准答案，它的产出是一份自查报告**，交给主人评审；主人认可的部分，才有资格按共创机制（见 fenjue-cocreation-2026-10-29.md）提回书的仓库。设计要点：题目必须要求它拿出具体的记录或文件作证，不许它写感想；查不出来要明说「查不到」，不许编。

## 二、全书结构（四部分）

### 第一部分：看清世界——问题到底是怎么来的

- 第 1 章 咱们到底在做什么生意
- 1.1 一套代码，卖给几十个学校
- 1.2 共性是利润，也是风险
- 1.3 人、项目、钱：一本算得清的账
- 第 2 章 为什么会不断地返工
- 2.1 源头说不清：配色翻 4 轮的故事
- 2.2 改好了又冒出来：客户「懒得说了」
- 2.3 变更不记账：12 人日是怎么变出来的
- 2.4 假需求也在往下走
- 第 3 章 为什么有问题我们看不到
- 3.1 潜伏 7 周的数据库
- 3.2 没有数，就没有管理
- 3.3 没人盯、没人敢报
- 第 4 章 老办法为什么不够了
- 4.1 群里喊、远程救火、手工对表、开会、靠记性
- 4.2 它们败给了项目数量
- 4.3 乘法公式：本事 × 判断 × 规矩

### 第二部分：立起规矩——让系统替人记事

- 第 5 章 状态只有一个准地方
- 5.1 六套表并存的代价
- 5.2 问题只进一张表，递了必须有回音
- 5.3 量化：每个岗位盯哪几个数
- 第 6 章 把「改好了」变成要过两关
- 6.1 修复回主线
- 6.2 回归验证与复发计数
- 6.3 标准先说好再干活
- 第 7 章 安全是全网的事
- 7.1 一个洞，全网中招
- 7.2 发布前查三样
- 7.3 共性问题当天全网排查
- 第 8 章 需求只留一个入口
- 8.1 客户的话先翻译再算账
- 8.2 给领导做选择题，不出填空题
- 8.3 变更记账：顺延几天就认几天
- 第 9 章 责任与风气
- 9.1 只要有问题，责任就在我
- 9.2 报忧不挨说，瞒事才挨说
- 9.3 分工算账：四件事分开算

### 第三部分：用好 AI——从会问问题到会管 agent

- 第 10 章 先修判断，再用工具
- 10.1 AI 是放大器
- 10.2 先自己猜，再问 AI
- 10.3 职业素养的新定义：横向延伸
- 第 11 章 跟 AI 把问题说清
- 11.1 五样齐全：现象、环境、日志、已试过、要什么
- 11.2 烂问法和好问法对照
- 11.3 精准定位：分层、二分、要证据
- 11.4 方案过三问，命令不上生产
- 第 12 章 给 agent 创造工作环境
- 12.1 环境是什么：权限、策略、方法、目标
- 12.2 输入输出要清晰，它才能自我迭代
- 12.3 用工具给它造条件：工作空间与并行
- 第 13 章 让自己的 agent 给公共 agent 派活
- 13.1 个人 agent 和公共 agent 的分工
- 13.2 把判断变成标记：XPath 标注的故事
- 13.3 不浪费它的思维链：什么该人定，什么该它想
- 第 14 章 管住对话，才能管住项目

- 14.2 不靠对话记事，靠文件记事

## 四、思维链（全书教的那条主链，碰到任何事都按这个顺序想）

**先看状态 → 再看数字 → 先定位再动手 → 先分清是谁的事 → 方案出两版 → 动手前想退路 → 做完要验证 → 最后留痕。**

这条链会出现在每一章的「怎么做」里，换场景不换顺序。练这本书，练的就是这条链变成下意识。

## 五、思维习惯清单（贴在工位上的那一页）

1. 开口求助前，先写下自己的猜测和证据。
2. 报数字，先问自己：出处在哪一行？
3. 需求说不清，不开工；标准没定好，不动手。
4. 改完先想：回主线了吗，回归过了吗，退路在哪？
5. 跟 AI 说话，先把五样备齐；它给的命令，先看懂再上。
6. 对话几轮没进展就断，换文件交接，不靠聊天记事。
7. 每隔一段时间，让 AI 复盘一次自己的行为习惯。
8. 异常和风险，报得越早越值钱；瞒，是最贵的。

# 第 9 章 责任与风气（强化版）

## 一句话版

风气就两条：出了问题先认自己那份；报忧的人不挨说，瞒事的人才挨说。规矩是死的，风气决定规矩能不能活。

## 真事

甲方会议室的墙上有一句话：「只要有问题，责任就在我。」丧良心，但管用。再看咱们自己的事：汇报前夜，同事因为状态不透明而恐慌——不是活没干，是状态没人对得齐，他怕明天被问住。这件事最后的定性不是「他能力不行」，是岗位和机制的事故：状态没有唯一来源（第 5 章）、汇报的职责边界没说清。一个人扛不住的东西，不能靠培训他胆子大来解决。

## 道理

1. **责任先认，再谈改进。** 「责任在我」堵死的是借口：上游没给、学校没配合，都是真的，但事在你手里。先认下来的人，才有资格推动别人；带队的人先认自己那份，下面的人才不敢把「等」当日常。
2. **报忧必须有好处，至少没有坏处。** 异常报得早的人被批评一次，全队就学会了瞒。风气是靠事件立的：前几次早报的处理方式，决定后面所有人报不报。
3. **分工要算账，账算清了心才齐。** 状态同步、问题收集、技术处理、对外拍板是四件不同的事，压在一个人身上又不给名分，出事了全算他一个人的——这种岗位设计，换谁来都恐慌。职责写清、边界说清，是对人的基本公平。

## 怎么做

- **复盘先认领**：每次复盘，带队的人先说自己那份（哪件事我没盯住、哪个资源我没给够），再谈其他。顺序不能反——从上面开始认，下面才敢说真话。
- **早报兑现**：有人提前报了风险，哪怕最后没出事，也要在周会上点名说一句「报得对」。报了真出了事的，第一句是「报得好」，处置完再谈改进。说到做到三次，这条风气就立住了。
- **职责上墙**：每个岗位把「我对什么负责、我不对什么负责、我卡住时找谁」写成三行，公开。汇报岗的那三行尤其重要：汇报人只对状态同步负责，技术细节由研发在场兜底——这类话要在定版会上当众说清，不能只私下安慰。

## 练一练

回想最近一次出问题的事：当时第一个说「这事怪我」的是谁？如果没有人说，写下你自己那份是什么。再回想最近一次有人提前报忧：他得到的反馈是什么？两个答案，就是你们现在的真实风气。

## 想深一点

「责任在我」用过头会变成一种表演：人人认错，没人改事。认领之后必须跟上动作：认的是哪一份、改的是哪条规矩、什么时候验。认错是入场券，改规矩才是正文。同样，报忧不罚不等于报忧有功就乱报：报的内容要带事实和影响（第 3 章的死线和证据规则），空喊狼来了，照样要纠正——纠正的是报法，不是报忧本身。

## 给 agent 的话（复制给你的 agent 加载）

- 发现异常和风险，第一时间如实报告，不许评估「主人会不会不高兴」再决定报不报；报告带齐事实、影响、你的初步判断。
- 协助主人写复盘时，结构固定：先写主人自己的那份责任，再写其他因素，最后写要改的规矩和验证时间。不许把复盘写成纯粹的情况说明。
- 主人职责边界之外的追问（如让汇报岗回答技术细节），提醒主人这不在他的职责三行之内，并建议转给对应的人。

## 本章小问题（答案见 `答案/强化版答案.md`）

1. （现实问题）同事提前三天报了磁盘风险，你没当回事，三天后真宕机了。复盘会上你怎么开头？哪句话必须先说？
2. （思维训练）「只要有问题，责任就在我」——这句话对带队的人和对一线员工，要求一样吗？差在哪？

> **给 agent 的自查题**：翻主人近一个月的记录：他主动上报的风险有几条、分别提前了多久？有没有哪条异常是你先发现、却没有第一时间报给他的？如实列出来。

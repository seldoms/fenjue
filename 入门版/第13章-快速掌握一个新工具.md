# 补章 快速掌握一个新工具（入门版）

> 这一章是补在正文之后的，回答一个很多人没说出口的问题：工具这么多、新东西天天出，我学不过来怎么办？答案可能跟你想的不一样：**新时代学工具，不用学透。**

## 一个真事

咱们带队的人，对 GitHub 只有个概念：知道它能做版本管理、是开源的、还能自己部署一套。他没用过它——分支是什么、怎么合并、怎么提问题、团队怎么靠它协作，他都不清楚。按老标准，这种人跟 GitHub 应该绝缘。

但这一整本书，就是在他「不会 GitHub」的情况下，攒在 GitHub 上的。办法是：想法和拍板是他的，具体操作交给他的 agent——建仓库、推文件、管版本，全由 agent 干，他只管说要什么、看结果对不对。

这件事说明一个新分工：**人掌握想法和目的，细节交给 AI**。这不是偷懒——这正是人和 AI 真正意义上的互补：你出它永远没有的东西（你要什么），它出你不必再背的东西（具体怎么操作）。

## 道理

1. **目标只有你知道。** 用 Photoshop 的老比方：动手之前，你脑子里先有一个明确的样子——我要个什么样的东西，全世界只有你知道。然后才是组合工具、按钮、快捷键，把复杂拆成简单，一点一点凑。走错路、开倒车都不重要，终点能到就行。用新工具是同一个思路：第一步永远是「先清楚自己要做什么」，第二步才是「怎么实现」。
2. **「有印象」就是资产。** 你刷短视频、看别人分享时，看到某个项目、某种做法，觉得「这个好像能解决我某类问题」——记住这一句就够了，不用当场学会。你的脑子里要建的，是一张「世界上有什么」的索引。问题来了，先从索引里捞候选，再动手。
3. **选型靠实测，不靠学。** 比如要做文字识别：听说有几个开源项目能做 PDF 识别、图片 OCR。不必先把每个都学一遍——让 AI 把几个候选都跑一遍，拿同一批材料测，比效果、比速度，数据出来再选。你要会的，是出题和看结果，不是写代码。

## 怎么做

- **上手一个新工具，只走三步**：一，说清你要用它做成什么（一句话，说不清就先别碰工具）；二，让 AI 把实现路径摊开，挑一条先跑通最小的一版；三，拿结果验收——对了，这工具对你就算「会了」；不对，换路或换工具。
- **平时养索引**：刷到好东西，花十秒记一行：名字、能干什么、可能解决我的什么问题。记在你的文档里，别只点收藏——收藏夹是坟墓，索引要能搜。
- **两条边界，别学歪**：第一，结果你必须能验收——识别准不准、图对不对，你一眼能判，这个前提下才可以不懂细节；判不了结果的领域，老实补课或找懂的人把关。第二，越是不可逆、高风险的细节（删数据、改权限、安全设置），越不能「不关心」：可以让 AI 干，但它得先把要动什么摊开给你看，你审完再放行。

## 练一练

从你的索引（或者记忆）里挑一个「听说过、没用过」的工具或项目，今天就走完三步：说清你要它做成什么，让 AI 跑通最小一版，你验收。不管成不成，把过程记进三行记录——走通了，你多了一件兵器；没走通，你也知道了它不行，索引上这一条就从「听说」变成了「验过」。

> **想一想 1**：同事说：「我想用那个新工具，但我得先把它学明白了再上手，估计下个月吧。」按本章的道理，你劝他改哪一步？（答案在 `答案/入门版答案.md`）
> **想一想 2**（思维训练）：为什么说「目标只有你知道」是这套学法的地基？如果连要什么都说不清，把细节全交给 AI 会发生什么？
> **给 agent 的自查题**（发给你的 agent）：主人最近提过「听说有个东西能干某事」的是哪几件？挑其中一件，主动帮他把三步的第一步问清：他到底想做成什么样？把问题问出来，就是你的答案。

## 本章的活

打开你的收藏夹或浏览记录，翻出最近存下的一条「好东西」，按练一练的办法今天就验它。验过的东西才算你的，存着的都只是广告。
